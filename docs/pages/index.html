Boring Log Viewer

Turn boring log data into a clean, consistent boring log drawing: graphic log, USCS symbols, material descriptions, samples, blow counts, laboratory results and groundwater, on one page.

You give it the data for one boring: the layers, the samples and what was measured on them. It draws the log for you, with standard soil symbols, a depth scale, a legend and a header. You can download the result as an SVG or PNG image, or print it to PDF.

Who it's for

The viewer was written for geotechnical engineers, engineering geologists, researchers and students who need to show boring logs, for example:

  • drawing logs for a report or a paper from data you already have in a spreadsheet or database;
  • looking at an AGS4 or DIGGS file someone sent you, without special software;
  • showing boring logs on a website. The case-history databases at nextgenerationliquefaction.org and vspdb.org draw their logs with it.

You don't need to be a programmer. If you can fill in a spreadsheet, you can write the data the viewer needs; the first tutorial walks through it.

Three ways to use it

1. On the web pagePaste or type your data, see the log update as you type, and download it. Nothing to install. Your data stays in your browser. 2. Open an AGS4 or DIGGS fileOpen a standard data-transfer file and the borings in it are drawn directly. 3. From a scriptSend the data from Python or any other program to the render API and get an image back. Good for drawing many logs at once. 4. A whole siteSend all the borings of a site together and get a page with suggested cross-sections, a 3D model, every log and a map.

What it draws

  • Header with the project, boring name, location, elevation, dates, drilling method, hammer and the references the data came from.
  • Depth and elevation scales, in metres or feet.
  • Groundwater levels, with the date and a note for each reading.
  • Graphic log using the USCS soil symbols of the Caltrans Soil and Rock Logging, Classification, and Presentation Manual (2010), plus 67 symbols for fill, pavement, organic and other materials, and rock types after the FGDC geologic map standard. If you don't give a symbol, it is worked out from the material description.
  • Material descriptions beside their layers, with leader lines when a long description has to be moved down, and notes at a single depth (such as "thin sand lens") in italics.
  • Samples: 22 sampler symbols (SPT, Modified California, Shelby tube, rock core, bulk and so on), sample numbers, blow counts, recovery.
  • Laboratory specimens, each at its own depth within its sample, with water content, total and dry unit weight, specific gravity, fines content, and liquid and plastic limits.
  • Your own columns, such as pocket penetrometer readings or undrained strength, with your own headings and widths.
  • Legend listing only the symbols that appear in this log.

Columns with no data are left out, so a log with only layers is a narrow, simple drawing, and one with full laboratory data gets every column.

For a site with several borings, the web page keeps them in tabs and shows them on a map, and the site view connects them in cross-sections and a 3D model.

Where the data comes from

The viewer reads a boring log written in JSON, a plain-text format for structured data. JSON looks like this:

{
  "schema_version": "1.0",
  "units": { "length": "ft" },
  "layers": [
    { "top": 0, "bottom": 4,  "description": "Brown, loose, moist, silty SAND" },
    { "top": 4, "bottom": 12, "description": "Gray, soft, wet, lean CLAY" }
  ]
}

That's a complete boring log: two layers, with depths in feet. Everything else (samples, blow counts, lab data, groundwater) is optional and added the same way. The data format reference lists every field.

It also reads AGS4 files (common in the UK and internationally) and DIGGS XML files (used by several US state DOTs), converting them to the same JSON. See Importing AGS4 and DIGGS.
