Data format reference

Every field the viewer reads, what it means, and what units it's in.

A boring log is one JSON object. Only schema_version and layers are required. The outline:

{
  "schema_version": "1.0",
  "units":       { ... },     how the numbers are measured
  "metadata":    { ... },     the header: project, boring name, location, drilling...
  "layers":      [ ... ],     strata, top to bottom (required)
  "samples":     [ ... ],     samples and blow counts, each with its lab specimens
  "groundwater": [ ... ],     water level readings
  "depth_notes": [ ... ],     observations at a single depth
  "references":  [ ... ],     where the data came from
  "patterns":    { ... },     your own hatches and sampler symbols
  "layout":      { ... }      the log's columns, widths and headings
}

(The notes on the right aren't part of the JSON.) A complete example: full-example.json. The formal definition is the JSON Schema, which many editors can use to check your file as you type.

General rules

  • Depths are measured down from the ground surface, in the length unit from units. They can't be negative. For each layer and sample, bottom must be greater than top.
  • Order doesn't matter. Layers and samples are sorted by depth before drawing.
  • null means "not given". "water_content": null is the same as leaving the field out, so database exports with empty cells work as they are.
  • Field names are checked. A misspelled name such as "descripton" is an error ("unknown property"), so typos don't silently lose data. Names are lower case, with underscores.
  • Gaps and overlaps between layers are allowed but reported as warnings, in case they're mistakes. A gap is left blank in the graphic log.

layers

The strata, one object per layer. At least one layer is required.

FieldMeaningExample
top, bottomRequired. Depths of the layer's top and bottom4.5, 6.0
descriptionMaterial description, as it should appear on the log"Gray, soft, wet, lean CLAY with sand"
uscsUSCS group symbol, an ASTM D2487 dual symbol (with -), or a borderline symbol (with /). It's checked against the description; see checking recorded symbols"CL", "SP-SM", "CL/CH"
hatchThe graphic log symbol, if you want to choose it: a USCS symbol, a material or rock code, a pair of them, a code from patterns, or "none" for blank"FILL", "SANDSTONE", "SP-FILL"
 
"layers": [
  { "top": 0,   "bottom": 1.2, "description": "Brown silty SAND (FILL)" },
  { "top": 1.2, "bottom": 4.5, "description": "Gray, soft, wet, lean CLAY", "uscs": "CL" },
  { "top": 4.5, "bottom": 9.0, "description": "SANDSTONE, weathered", "hatch": "SANDSTONE" }
]

The USCS symbols are GW, GP, GM, GC, SW, SP, SM, SC, ML, CL, OL, MH, CH, OH and PT. A value that isn't a possible symbol but contains one, such as GP-GW or SM-G (common in older logs), is accepted with a warning; one with no real symbol in it, such as XX, is an error. The material and rock codes, and how the symbol is chosen when you don't give one, are in Graphic log and soil symbols.

Older data

Laboratory results written on the sample itself (water_content, liquid_limit and so on), and a sample description, are still accepted with a warning. See results on the sample.

]

depth_notes

Observations at a single depth within a layer, such as a thin lens, a change in color, or "trace gravel". They're drawn in italics under the layer's description, with a tick at their depth. Both fields are required.

"depth_notes": [
  { "depth": 7.6, "description": "thin clayey sand lens" }
]

references

Where the data came from: the report, paper or database. Listed in the header. text is required; a web address in url is shown after the text and is a clickable link in an SVG.

"references": [
  { "text": "Example Geotechnical Consultants (2019). Geotechnical investigation report.",
    "url": "https://example.com/report.pdf" },
  { "text": "Personal communication, J. Doe, 2020" }
]

patterns

Your own graphic log symbols and sampler symbols. This section is usually written for you by the viewer's Hatches… window; see Your own hatches for how it works and how to write one by hand.

"patterns": {
  "SLOPE": {
    "name": "Sloping lines",
    "svg": "<svg viewBox='0 0 40 20'><line x1='0' y1='20' x2='40' y2='0' stroke='black'/></svg>"
  }
}

layout

The log's columns, their order, relative widths and headings, and its width and font size, saved with the data. Without it, the built-in layout is used. It's usually written for you by the viewer's Layout… window; see Columns and layout.

"layout": {
  "width": 1000,
  "columns": [
    "depth", "graphic", { "id": "description", "width": 25, "label": "Soil description" },
    "sample_type", "sample_name", "blow_count",
    { "id": "pp", "source": "sample", "field": "pocket_pen", "label": "PP (tsf)" },
    "remarks"
  ]
}
